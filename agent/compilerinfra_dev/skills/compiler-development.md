# Developing a linked compiler

Open the installed product and call `layout`. Read the levels in order, the contract of each node, its parent, and the exit attachment. Use the unit and source location to find the registration that executes at the relevant boundary. Call `inspect` to discover installed actions and skills.

Place incoming lowering in the child node. A change that belongs to just one downstream implementation lives in its exit. When multiple exits need a representation, introduce a node for it. Put shared analyses at the nearest common ancestor that can express their facts. The runtime consumes the public ABI of its exit.

Use v0.5 mechanisms for all new optimizations and target rules: express multi-choice decisions via `DecisionFamily`, emit terminal operations with `PrintRule::format` or `PrintRule::local` (`LocalOpView`, without inspecting sibling operations or machine facts), declare implementation contracts via `TypedContract` / `ContractOpInterface` / `MemoryEffectOpInterface` with standard `mlir::arith::FastMathFlags` and function `llvm::DenormalMode`, and prove narrow addresses, value replay, and tail bounds with `compilerinfra/Proofs.h`. Call `inspect parity` and `inspect readiness` to check sibling-exit capability alignment and migration/calibration coverage.

Derive a configuration to try an already linked strategy, or pass a source patch to build a new candidate. Compile the same root input through a named boundary in both candidates. Pass the returned compilation ID to `explain` and `impact` to distinguish a reachable exit, a configured strategy and an actual hit. Compare emitted IR at the same boundary, then measure the complete program with the external Bench and its existing numerical contract. Adopt the candidate to apply its source and configuration and reinstall the baseline, or discard its handle.
