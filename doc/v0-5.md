# CompilerInfra v0.5：局部发射、类型化合同、共用证明与对齐就绪视图

**状态：v0.5.2 生效。** v0.5 的核心目标是：当开发者或 coding agent 新增一项优化时，只需声明一次“选择、前提、效果”，即可自动获得候选登记、IR 绑定、检查点恢复校验和 `explain` 诊断；当关键前提缺失时，框架在引入该决定的边界直接给出可定位的错误，而非依赖事后人工提醒。设计保持领域无关，沿用 v0.3/v0.4 的编译树、`DecisionFamily`、局部估算器、分档过滤与一步回滚。[框架总览](framework.md) · [终端发射](terminal-emission.md) · [性能决定](performance.md)

## 1. 解决的框架缺口

| 反复出现的失效模式 | 0.4.2 无法阻断的根因 | v0.5 的机械约束 |
|---|---|---|
| 执行结构藏进末端打印 | 打印回调直接持有 `mlir::Operation &`，可偷看父子/兄弟节点并拼出循环、临时缓冲或同步 | 默认打印规则只接收 `LocalOpView` 局部视图与声明式格式模板；无法访问相邻 op 或机器事实；自定义规则必须显式标为 `custom` 并列入 `inspect` |
| 合同字段完备但校验强度悬殊 | `operands`、`layout`、`effects`、`numerical` 均为自由字符串，检查完全依赖手写回调 | 用类型化合同与 MLIR `MemoryEffectOpInterface` 统一生成候选合法性与恢复检查；未迁移旧合同在 `readiness` 标出边界 |
| 数值许可各自自造检查 | 正向变换与检查点恢复使用不同口径，或自造复杂的授权溯源台账 | 直接采用成熟编译器标准：操作级 `mlir::arith::FastMathFlags` + 函数级 `llvm::DenormalMode` + 编译配置默认值；标志本身即 IR 语义，不做额外出处追溯 |
| 地址收窄、值回放、尾段越界复发 | 各出口重复手写遍历、溢出判断与别名扫描，常漏查子 region 或中间写 | 框架提供窄地址、值可回放、尾段访问三类共用证明原语；未知一律走保守回退，产品仅为自有 op 实现标准 interface |
| 同源出口能力参差、证据状态不清 | 注册表只列已有实现，无法区分硬件不支持、尚未开发或漏选；校准与留出记录缺乏按出口汇总 | 新增只读 `inspect parity` 与 `inspect readiness`，并核对 runtime 回执与外部 Bench 测量协议的一致性 |

## 2. P0 核心机制

### 2.1 决定进入 IR，打印器只拿局部视图

凡存在多个合法方案且改变工作归属、物化缓冲、同步作用域或实现绑定的选择，必须通过 `DecisionFamily` 产出结构化终端 IR 并进入 `explain`。`legalize` 只查询合法性所需事实；唯一合法的降级可直接改写。

终端发射区分两类规则（见 `compilerinfra/Terminal.h`）：

- **局部规则（默认）**：通过 `PrintRule::local(...)` 或声明式格式模板 `PrintRule::format(...)` 登记。回调只获得 `LocalOpView`（本操作名、已绑定实现符号、已分配的输入/输出值名、自身属性字典、当前 region/block 序号与块参数名）和只追加输出的 `PrintContext`（缩进、行追加、当前输出文件名与已绑定微核源码；`PrintContext` 不暴露已完成文本字典，禁止改写早先输出）。回调拿不到 `mlir::Operation &`、父/兄弟节点或 `TargetProfile` / `MachineFacts`，从签名上杜绝“看邻近 op 临时补写循环、打包或屏障”。注意：C++ 闭包捕获外部可变状态无法单靠回调签名阻断，属于代码审查与独立审计核查范围。
- **显式自定义规则（受控豁免）**：接收 `mlir::Operation &` 的回调不提供隐式类型转换，确需使用必须显式调用 `PrintRule::custom(..., reason)` 登记并注明理由。框架在链接清单中单独记录每个出口的 `custom_print_rules`（操作名与理由），并在 `inspect` 和 `inspect readiness` 中完整列出，供人工与独立审计核查。

### 2.2 类型化合同与标准数值语义

多实现目标操作除基础元信息外，可通过 `TypedContract` 与标准 MLIR interface 声明可机械执行的约束（见 `compilerinfra/Contract.h`、`compilerinfra/Terminal.h`）：

- **形状、类型与布局**：操作数/结果秩或形状关系、允许的元素与累加类型、对齐字节数、地址空间与打包谓词。
- **可观察副作用**：对接 MLIR `MemoryEffectOpInterface`（`Read`、`Write`、`Allocate`、`Free`）。目标微核内部允许多条指令与局部同步，跨操作可见的读写与分配必须与合同声明一致；框架在候选筛选与终端边界恢复时统一核验。
- **数值语义（FastMath + DenormalMode）**：
  - **操作级标志**：采用 MLIR `mlir::arith::FastMathFlags`（`reassoc`、`contract`、`afn`、`nnan`、`ninf`、`nsz`、`arcp`、`fast`），优先读取 `ArithFastMathInterface` 或操作上的 `"fastmath"` 属性。
  - **函数级次正规模式**：采用 LLVM `llvm::DenormalMode`（`IEEE`、`PreserveSign`、`PositiveZero`、`Dynamic`，分别约束输出与输入），读取包裹函数上的 `"denormal-fp-math"`（或 `"ci.denormal_mode"`）属性。
  - **全局默认配置**：编译器配置顶层支持可选 `"numerical": {"fastmath": "...", "denormal_mode": "..."}`（缺省为 `none` 与 `ieee,ieee`）。
  - **改写与恢复规则**：变换前通过 `hasFastMath` / `allowsSubnormalFlush` 检查参与操作的有效标志，改写生成的新操作通过 `propagateNumericalFlags` 继承交集标志。**不做“记录消费了哪些许可并在恢复时回溯根 IR 复验”的自造机制**：IR 上的标志与函数模式本身就是语义定义，检查点恢复只验证 IR 良构与类型化合同满足性。诸如在线重缩放所需的有限值或舍入边界前提，作为该变换自身的合法性谓词处理。

### 2.3 三类共用证明原语

`compilerinfra/Proofs.h` 提供三项可复用的静态证明查询，产品只需在自定义方言操作上实现 `InferIntRangeInterface` 或 `MemoryEffectOpInterface`：

1. **窄地址证明（`proveNarrowAddress`）**：在给定根操作及其**全部嵌套 region/block** 上运行 `DeadCodeAnalysis` 与 `IntegerRangeAnalysis`，核对索引值、步长乘加中间值及位宽截断/扩展的符号与无符号上下界是否无回绕地落入目标位宽（如有符号/无符号 32 位）。任一中间值范围未知或可能越界时返回未证明及定位信息，调用方保留宽地址（如 `i64`）。
2. **值可回放证明（`proveValueReplay`）**：基于 `MemoryEffectOpInterface` 与 `mlir::AliasAnalysis`（`ModRef`），检查首次读取与回放使用之间所有可达执行路径（含循环回边与嵌套区域）上的中间操作：若首次读取依赖的任一内存资源存在 `Mod`（潜在别名写），或中间出现未声明内存效果且非无副作用的操作，则判为不可回放，调用方回退为重新计算。
3. **尾段访问证明（`proveTailAccess`）**：结合静态维度与 `IntegerRangeAnalysis` 逐维核对访问起点、分块跨度、步长与底层张量上界，区分 `ExactDivisible`（整除免掩码）、`MaskedInBounds`（带显式有效域掩码或合法填充）与 `Unproven`（回退至掩码或标量尾段）。

## 3. P1 可见性、测量协议与渐进迁移

### 3.1 `inspect parity`

父节点通过 `Unit::capabilities` 登记语义能力（名称、类别与说明）；子出口通过 `Unit::parity` 按目标或架构声明三态之一：
- `Implemented`：绑定具体实现合同、策略或转换组件名；
- `Unsupported`：声明目标硬件或下游工具链限制及明确原因；
- `Todo`：能力合法但尚未实现。

子出口未声明的父节点能力在链接视图中自动生成 `Todo`。`inspect parity` 同时核对已登记符号是否存在于组件目录（`registered`），以及在当前编译器配置或已观测编译回执中是否实际启用/命中（`selected`）。

### 3.2 测量协议核对与 `inspect readiness`

- **轻量测量协议核对**：`compilerinfra.performance.check_protocol(protocol, receipt)` 对照外部 Bench 请求的协议（计时范围、预热/缓存冲刷、设备、线程数、数值配置）与运行时回执报告的实际执行条件；任一字段不符即标记 `comparable=False` 并列出差异项，避免不同口径读数混入比较或模型计分。
- **只读 `inspect readiness`**：按出口汇总当前版本的就绪度边界，不引入额外审批流程：
  - v0.5 迁移覆盖率（局部/模板打印规则数 vs `custom` 打印规则列表；类型化合同数 vs 旧字符串合同列表；`parity` 待做项）；
  - 已选校准配置（`calibrationProfile`）及机器事实来源版本；
  - 留出集 `model-accuracy` 摘要（传入记录文件时一并计算所选/最佳比、成对准确率与排除批次）；
  - 当前工作区与已安装基线的指纹一致性及可回滚状态，并显式列出缺项（`missing`）。

## 3.3 渐进迁移约定

接收 `mlir::Operation &` 的旧式打印回调必须显式通过 `PrintRule::custom(..., reason)` 声明并在 `readiness` 列出；旧字符串字段合同继续工作但标记为 `legacy_string_contract`。所有新增出口、目标操作与优化路径一律使用 `LocalOpView`/格式模板、`TypedContract`、标准 `FastMathFlags` + `DenormalMode` 及 `Proofs.h` 保守共用证明。
